🔧 Ajuda — Phase-Field 3D (Al–Cu)

Como compilar e rodar o solver 3D de campo de fase (fase + soluto + temperatura, diferenças finitas, Fortran) em CPU com OpenMP ou na placa gráfica (OpenMP target offload). O mesmo código-fonte serve aos dois caminhos: o executável detecta a GPU em tempo de execução (omp_get_num_devices()) e, se não houver, roda em CPU.

1. Requisitos

AlvoAmbienteCompilador
GPU NVIDIA recomendado WSL2 Ubuntu + driver NVIDIA do Windows NVIDIA HPC SDK (nvfortran) em /opt/nvidia/hpc_sdk/Linux_x86_64/<versão>
CPU OpenMP Windows (PowerShell / cmd) Intel oneAPI ifx + Visual Studio 2022 (linker)
GPU Intel fp64 Windows ifx com -Qopenmp-targets:spir64

Placa desta máquina: NVIDIA GeForce RTX 4050 Laptop GPU (6 GB), compute capability 8.9. Confira a qualquer momento com:

nvidia-smi
Nota: a iGPU Intel Iris Xe não tem fp64 em hardware e todos os kernels são em precisão dupla — use a GPU NVIDIA ou a CPU.

2. Estrutura do projeto

phasefield/
├── source/
│   ├── principal.f90             # laço temporal, escolha CPU/GPU, timing/log
│   ├── variaveis.f90             # módulo de variáveis globais + RNG (declare target)
│   ├── entrada.f90               # lê entrada.dat, aloca e inicializa os campos
│   ├── W0_E0.f90  auxiliar.f90   # W0, E0 e mobilidade M0
│   ├── equacao_campo_fase.f90    # kernel da fase (anisotropia cúbica)
│   ├── concentracao_soluto.f90   # kernel do soluto
│   ├── temperatura.f90           # kernel do calor
│   ├── diagnosticos.f90          # L2, min/max, soluto total, energia livre
│   ├── saida.f90                 # grava ./output/saida_*.dat (Tecplot POINT)
│   └── *_body.inc                # corpo único dos kernels (CPU e GPU idênticos)
├── entrada.dat                   # parâmetros físicos, malha, tempo
├── phasefield_gpu.sh             # build + run na GPU NVIDIA (WSL2)
├── parallel_compile.bat          # build CPU OpenMP  → phasefield3d_omp.exe
├── compile_gpu.bat               # build GPU Intel   → phasefield3d_gpu.exe
├── setvars.bat                   # carrega o ambiente Intel oneAPI
├── set_OpenMP_environment.bat    # OMP_NUM_THREADS / PROC_BIND / PLACES
├── show_OpenMP_environment.bat   # mostra as variáveis OpenMP atuais
├── output/                       # snapshots (grandes; fora do git)
└── performance_log.txt           # log acumulado de desempenho do run
Obsoletos: compile.bat e build.ps1 são da versão 2D (geram phasefield2d.exe, sem OpenMP e sem diagnosticos.f90). Use parallel_compile.bat no lugar.

3. Início rápido (cola)

Na GPU NVIDIA (terminal WSL / Ubuntu)

cd /mnt/c/Users/ileao/OneDrive/Documentos/phasefield
bash phasefield_gpu.sh build      # compila → phasefield3d_gpu_wsl
bash phasefield_gpu.sh run 30     # teste rápido: para sozinho após 30 s
bash phasefield_gpu.sh run        # run completo (até stoptime; Ctrl+C para parar)

Na CPU com OpenMP (Prompt de Comando cmd, na pasta do projeto)

call setvars.bat                  :: ambiente Intel oneAPI (uma vez por janela)
call parallel_compile.bat         :: compila → phasefield3d_omp.exe
call set_OpenMP_environment.bat   :: 8 threads, fixadas nos núcleos
phasefield3d_omp.exe
Como saber onde está rodando: logo no início o programa imprime uma das duas linhas abaixo; o mesmo aparece em Execution Device no resumo de cada escrita. 
### GPU offload ENABLED -- 1 OpenMP target device(s) detected ###
### No OpenMP target device -- running CPU OpenMP path ###

4. GPU NVIDIA (WSL2 + nvfortran)

Abrir o terminal

No Windows: menu Iniciar → Ubuntu (ou wsl no PowerShell). Os discos do Windows ficam em /mnt/c/….

Comandos do script phasefield_gpu.sh

ComandoO que faz
bash phasefield_gpu.shcompila se ainda não existir o executável e roda
bash phasefield_gpu.sh buildsó compila (nvfortran -mp=gpu -gpu=ccXX,cudaYY -O3)
bash phasefield_gpu.sh runsó roda (exige build anterior)
bash phasefield_gpu.sh run 60roda e encerra após 60 s (teste)
bash phasefield_gpu.sh rebuildrecompila do zero e roda — use sempre que alterar um .f90/.inc

O script detecta sozinho a versão do HPC SDK, o CUDA empacotado e a compute capability da placa. Variáveis para forçar outro comportamento:

VariávelEfeito
CC=89força a compute capability (RTX 40xx = 89, A100 = 80)
STRICT=0permite cair na CPU se a GPU falhar. Por padrão (STRICT=1) o script exporta OMP_TARGET_OFFLOAD=MANDATORY e o programa aborta em vez de rodar silenciosamente na CPU
CC=89 bash phasefield_gpu.sh rebuild
STRICT=0 bash phasefield_gpu.sh run

Rodar em segundo plano (sobrevive ao fechar o terminal)

nohup bash phasefield_gpu.sh run > run.log 2>&1 &
tail -f run.log                   # acompanhar; Ctrl+C sai do tail, não do run
tail -f performance_log.txt       # só os resumos de desempenho
pkill phasefield3d_gpu_wsl        # encerrar o run

Acompanhar a placa

watch -n 2 nvidia-smi             # uso da GPU (%) e memória ocupada
WSL2: o driver CUDA (libcuda.so.1) fica em /usr/lib/wsl/lib. O script já põe essa pasta no LD_LIBRARY_PATH. Se você chamar ./phasefield3d_gpu_wsl diretamente, sem o script, o runtime pode ver 0 dispositivos e rodar na CPU.

Forçar CPU usando o binário da GPU

OMP_TARGET_OFFLOAD=DISABLED OMP_NUM_THREADS=8 ./phasefield3d_gpu_wsl

5. CPU OpenMP (Windows + ifx)

1. Carregar o ambiente Intel

Abra um Prompt de Comando (cmd) na pasta do projeto e rode:

cd C:\Users\ileao\OneDrive\Documentos\phasefield
call setvars.bat

Isso chama C:\Program Files (x86)\Intel\oneAPI\setvars.bat (ifx + linker do Visual Studio). Vale só para aquela janela. Alternativa: menu Iniciar → Intel oneAPI command prompt for Intel 64 for Visual Studio 2022.

2. Compilar

call parallel_compile.bat

Equivale a:

ifx -Qopenmp -O2 source\variaveis.f90 source\auxiliar.f90 ^
    source\concentracao_soluto.f90 source\diagnosticos.f90 source\entrada.f90 ^
    source\equacao_campo_fase.f90 source\principal.f90 source\saida.f90 ^
    source\temperatura.f90 source\W0_E0.f90 -o phasefield3d_omp.exe
Atenção: no Windows a opção é -Qopenmp com Q maiúsculo. Com -qopenmp o ifx ignora e o executável sai serial. Opcional: -QxHost otimiza para o processador desta máquina.

3. Configurar threads e rodar

call set_OpenMP_environment.bat
phasefield3d_omp.exe

Para guardar a saída da tela em arquivo:

phasefield3d_omp.exe > run.log 2>&1

Pelo PowerShell

cmd /c "call setvars.bat && call parallel_compile.bat"
$env:OMP_NUM_THREADS = 8; $env:OMP_PROC_BIND = "close"; $env:OMP_PLACES = "cores"
$env:PATH = "C:\Program Files (x86)\Intel\oneAPI\compiler\latest\bin;$env:PATH"
.\phasefield3d_omp.exe

A terceira linha só é necessária se aparecer erro de libiomp5md.dll não encontrada.

CPU no WSL (alternativa)

Com o binário do phasefield_gpu.sh e OMP_TARGET_OFFLOAD=DISABLED — ver § 4.

6. Threads e afinidade (OpenMP)

VariávelValor usadoSignificado
OMP_NUM_THREADS8número de threads (comece pelo número de núcleos físicos)
OMP_PROC_BINDclosefixa cada thread num núcleo, vizinhas entre si
OMP_PLACEScoresuma thread por núcleo físico (sem hyper-threading)
KMP_AFFINITY(alternativa Intel)granularity=fine,compact,1,0
call set_OpenMP_environment.bat     :: define e mostra os valores
call show_OpenMP_environment.bat    :: só mostra
Por que fixar: sem OMP_PROC_BIND / OMP_PLACES, 8 threads chegaram a rodar mais devagar que 4 nesta máquina (threads migrando entre núcleos). Ao trocar o número de threads, compare o Average Time/Step do log.

7. GPU Intel (ifx, spir64)

call setvars.bat
call compile_gpu.bat              :: → phasefield3d_gpu.exe
set LIBOMPTARGET_DEBUG=1          :: opcional: mostra o uso do dispositivo
phasefield3d_gpu.exe

Compila com -Qiopenmp -Qopenmp-targets:spir64. Sem GPU Intel com fp64, o mesmo executável roda no caminho CPU. Nesta máquina use a NVIDIA (§ 4).

8. Arquivo de entrada (entrada.dat)

Lido da pasta de onde o programa é chamado. Cada linha: o primeiro número é o valor usado; o resto da linha (outros números, comentário após |) é ignorado. As 3 primeiras linhas são cabeçalho.

ParâmetroObservação
Nx, Ny, Nzpontos da malha; o crescimento parte do plano j ≤ 4 (direção y)
dx, dy, dzespaçamento [m]
DELTA_Tignorado: recalculado em entrada.f90 como dx²/(12·D_liq) (metade do limite de estabilidade 3D)
DELTA_EPSLONforça da anisotropia cúbica
Thin_Interfaceespessura da interface = valor × dx
ajustemultiplica E0 (tensão superficial efetiva) e M0
stoptimetempo físico de parada [s]
WriteFileD_timeCounternº de passos entre escritas
TP (última linha)temperatura isotérmica [K] usada nas equações de fase e soluto. Se a linha faltar, usa 919 K e avisa na tela. O início do run mostra TP, Cl_eq e a liquidus TL(C0) = Tm − Me·C0: super-resfriamento = TL(C0) − TP

Linha seguinte ao TP (opcional): tipo_inicial R_semente — 0 = frente plana em j ≤ 4; 1 = semente esférica no centro com raio R_semente (em células). Convenção do arquivo: o valor usado vem primeiro, os anteriores ficam ao lado. O original está em entrada.dat.backup.

Atenção: o T0 do arquivo não controla o super-resfriamento — quem controla é o TP.

Mudou só o entrada.dat? Não precisa recompilar — basta rodar de novo.

Casos em pastas separadas

O programa lê ./entrada.dat e grava em ./output/ da pasta atual, então cada caso pode ter sua pasta. Exemplo: casos/teste_dendrita/ (200×400×200, ajuste = 1, TP = 915 K):

# WSL / GPU (compile antes com: bash phasefield_gpu.sh build)
cd casos/teste_dendrita
OMP_TARGET_OFFLOAD=MANDATORY LD_LIBRARY_PATH=/usr/lib/wsl/lib:$LD_LIBRARY_PATH \
    ../../phasefield3d_gpu_wsl

:: Windows / CPU
cd casos\teste_dendrita
..\..\phasefield3d_omp.exe
WSL: rodando o binário direto (fora do script), o LD_LIBRARY_PATH precisa incluir também as bibliotecas do HPC SDK se der erro de .so não encontrada — o mais simples é copiar phasefield_gpu.sh e o executável para a pasta do caso e usar bash phasefield_gpu.sh run lá.

Bloco de tempo (a cada escrita)

Execution Device       : GPU (OpenMP target offload)
Average Time/Step      : 0.93047 s
Completed              : 1.37 %

Use Average Time/Step para comparar CPU × GPU e números de threads. A estimativa de tempo restante usa o stoptime.

10. Desempenho e memória

  • Memória ≈ Nx·Ny·Nz × 7 campos × 8 bytes na GPU (mais ~4 campos na RAM). Ex.: 50×450×900 ≈ 20 milhões de pontos → ~1,1 GB na GPU. A RTX 4050 tem 6 GB: até ~100 milhões de pontos.
  • OneDrive + WSL é lento (ponte 9p e sincronização). Para runs longos, copie para o Linux e rode lá: 
    cp -r /mnt/c/Users/ileao/OneDrive/Documentos/phasefield ~/phasefield
cd ~/phasefield && bash phasefield_gpu.sh rebuild
# depois: copiar os resultados de volta
cp ~/phasefield/output/*.dat /mnt/c/Users/ileao/Documents/resultados/
  • Snapshots são o maior custo de disco. Aumente WriteFileD_timeCounter para escrever menos.
  • Pause a sincronização do OneDrive durante runs que escrevem em output/.
